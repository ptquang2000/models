Curriculum

The mission is the target. This file is the path. The path has one core track and one optional track. The core track has seven study elements. Each element teaches one model from the ground up and ends at a gate.

Status lives in progress.html. Math assignments live in math-map.html. The teaching method comes from ../docs/teach/SKILL.md. This file says what to study, in what order, and what must be true when an element is done.

The study element

A study element is the unit of work. It has five parts. The full template is in ../study/TEMPLATE.md. The first element is in ../study/0000-lab-harness.md.

Part Output Status after the part
1. Diagnostic One closed-book question todo
2. Concept lesson One idea, one numeric example, one source section reading
3. Reference card Definition, formula, failure mode reading
4. Build Code from a blank file implemented
5. Explain-back Answer without notes explained

The status ladder is in progress.html. A model is done only at verified + explained. The concept lesson is an HTML lesson in ../lessons/. The reference card is an HTML card in ../reference/. Both start when the element starts, not before.

The study element is the contract. The lesson is the teaching. The reference card is the compression. The build is the learner's work. The TA does not write the model, the loss, the gradient, or the update rule.

Element 0 has an HTML lesson at ../lessons/0000-lab-harness.html. The next lesson starts when the next element starts, or earlier if a gap appears.

Prerequisite contract: programming

Programming is a prerequisite. The path does not teach Rust. It tests the contract once, before element 0. The learner must be able to:

  1. Write a Rust function that takes a slice and returns a value.
  2. Use a fixed-size array and a slice with explicit indices.
  3. Read a text file and parse numbers from it.
  4. Write a #[test] and run it with the build script.
  5. State the shape of a 2D array and the meaning of each axis.
  6. Use the command line to build, run, and check the code.

The diagnostic is in ../study/0000-lab-harness.md. A failure adds a repair unit from The Rust Programming Language, chapters 3–4, 8, and 11. The repair unit is a prerequisite study element. It does not change the core path.

Gap-fill protocol

A gap is a missing prerequisite. A failed diagnostic or a failed gate is evidence of a gap. The rule:

  1. Name the missing fundamental.
  2. Add a prerequisite study element to ../study/.
  3. Give it a source and a status in progress.html.
  4. Pass the prerequisite gate.
  5. Return to the main element.

The main element does not move to blocked until two attempts produce no new information. A gap is not a failure. It is a path update.

Reading track

Every element has one primary source. Read it before the concept lesson. Stop at the stated point. The source wins if a section number disagrees with this file.

ID Element Primary source Stop at What it answers
0 Lab harness ISL §2.2, Assessing Model Accuracy the Python lab why held-out error, not training error, estimates performance
1 Linear regression, closed form ISL §3.1–3.2 §3.3 what least squares estimates, and what R² does and does not say
2 Linear regression, gradient descent Boyd & Vandenberghe ch. 5, the gradient-descent part Newton's method step size, convergence, why scaling changes the path
5 Logistic regression ISL §4.1–4.3, §4.4.2 pp. 155–156, §6.2.1 §4.4.3 log-odds, sigmoid, why log-loss and not squared error
8 k-means ISL §12.4.1 §12.4.2 the within-cluster objective, and why Lloyd cannot increase it
11 Naive Bayes ISL §4.4, the naive Bayes part §4.5 the independence assumption, and why it still works
13 Capstone ISL ch. 5, Resampling Methods the lab validation vs. cross-validation, reading a learning curve

Rules:

  1. One primary source per element. The rest of the list stays shut until that element is done.
  2. Section-level and capped. The "stop at" column is part of the assignment, not a suggestion.
  3. Verify the section when the element starts. Chapter numbers here are safe. Section numbers get checked against the PDF. The source wins if they disagree.
  4. No element starts until three things are true: the primary source is read, every term in the element contract is defined in words, and the acceptance test is written down before the code.
  5. Reading is not progress. An element moves to verified on tests, never on pages read. A term enters glossary.html only after it is used correctly.
  6. A starter model counts as implemented only from a blank file. Close the reference and the previous code. Write the model again. A model copied from a reference is a demo, not verified.
  7. Every element has two gates. Write the acceptance test and one explain-back question before the code. The element passes when the tests pass and the answer is correct without notes.
  8. The test set is read once. Fit the scaler on train. Make every choice on train or validation. Touch the test set only for the final number.

An acceptance test is the written statement of what must be true for an element to count as done. Write it before any code exists. It pins observable behavior: outputs, invariants, and error cases. It does not pin the internal steps. The implementation cannot define its own success.

A test enforces a rule. It cannot invent one. An element can contain a free choice. Examples are a size rule for remainders, a tie-break, and a default tolerance. Write the choice in prose beside the test. Then let the test enforce it. Test-first does not remove the decision.

Capstone

One dataset, one report, no new model code. The report has:

  • Baseline (mean or majority class), starter model, upgrade model, same split and metric.
  • Cross-validation numbers for the final comparison.
  • Learning curves and one failure case per model.
  • One paragraph per upgrade: when it beats the starter, and the source for the claim.
  • A short written defence: why this model, what it assumes, where it breaks, what you would do with 10× more data.
  • One reproducibility command that regenerates every number.

Acceptance: the report's claims are checkable with the command. No metric comes from training data alone. The model choice follows a validation number, not a preference.

Datasets

Use small, local, fast data. Loading a checked-in CSV or generating synthetic data is fine. Using an ML crate's estimators inside model code is not.

Choose the capstone dataset and its problem type before element 1. Record the choice in ../NOTES.md. Choose one small set for each other element.

Element Suggested data
Regression California housing (subset), or a synthetic nonlinear function
Classification Breast cancer, wine, or a synthetic two-moons set
Clustering Iris without labels, synthetic blobs, moons, concentric circles
